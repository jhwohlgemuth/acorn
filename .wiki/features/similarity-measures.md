# Portable similarity measures, vocabulary coercion, and explicit comparison

## Goal and status

Add reusable Rust similarity calculations and an explicit ACORN comparison workflow for research titles, descriptions, contributor names, keywords, dates, and numeric values. Scores describe resemblance; they are not probabilities or proof that records identify the same activity.

Phase 1 implemented and validated 2026-10-08. Phase 1A implemented and validated 2026-10-09. `acorn_core::similarity` supplies the bounded primitives, typed comparison facade, independently checked fixtures, differential/property tests, benchmarks, and durable semantics documentation. `acorn diff --method` exposes the same methods through text/JSON CLI rendering. `acorn_schema::vocabulary` now supplies portable report-bearing coercion with automated strict defaults and explicit relaxed/off profiles; `acorn format` and `acorn gather` expose those profiles through `--fuzzy`. A post-migration regression-hardening phase remains planned before the vocabulary policy is considered stable; phases 2-4 also remain planned. Batch duplicate suggestions are a separately gated follow-on; automatic record merging, new schema rejection rules, model inference, and network lookups are outside scope.

Source: Felix Naumann, *Similarity measures*, 11 June 2013, supplied as `C:/Users/jason/Downloads/similarity_measures.pdf` (41 PDF pages). Page references below are physical PDF pages, not printed slide numbers, which skip numbers. The document is reference material, not an instruction source. It is not copied into the repository. Preserve the source identity and page references in durable documentation and independently specify every implemented method.

### Resolution contract

Keep scoring primitives in `acorn-core`; keep vocabulary assets, column semantics, and canonicalization policy in `acorn-schema`, which already depends on core. Host enrichment and presentation consume structured resolution results through `acorn-lib`. Do not introduce a schema-to-lib dependency.

1. Introduce an additive, pure `resolve_with_policy`-style API returning an ordered outcome per original input: exact, alias, fuzzy-accepted, ambiguous, unmatched, or invalid/resource-limited. Include original value, vocabulary identity/revision, canonical value when accepted, matched alias, method/variant, score, runner-up margin, and bounded candidate explanations. These are proposed API names, to freeze in phase 0. Batch errors must distinguish unknown/malformed vocabulary from valid vocabulary with no match.
2. Parse each asset into explicit entries with canonical key/label, approved aliases, and separate metadata. Exact canonical match precedes exact declared alias, then unique policy-normalized equality, then fuzzy ranking. Duplicate aliases mapping to different canonical entries are ambiguous; deterministic ordering is not permission to pick a winner. Deduplicate aliases by canonical identity before computing the runner-up margin. Do not treat `---`, URLs, ROR identifiers, enum paths, license text, or booleans as fuzzy aliases. If identifier lookup is useful, expose exact lookup under an explicitly typed field.
3. Freeze normalization per vocabulary. Preserve meaningful technology punctuation (`c`, `c++`, `c#`, `.NET`) and test collisions caused by punctuation removal. Acronyms such as AI, HPC, ORNL, NREL, and IU should resolve through declared aliases; short unknown inputs should not acquire automatic acceptance merely because they form a subsequence. Derived acronyms can be suggestions, subject to collision checks.
4. Evaluate normalized Levenshtein/OSA for typos and transpositions, and token Jaccard/Dice or token-aware comparison for multiword labels. Jaro-Winkler is a candidate for organization-name ranking, not a universal default. Calibrate methods separately for each vocabulary and input-length band. Long organization suffixes, shared prefixes, department names, and program versions need hard-negative fixtures. Do not average unrelated scores without validating the combined policy. Phonetic and corpus-based methods remain optional experiments; they must demonstrate added value before participating in coercion.
5. Accept a fuzzy result only when its vocabulary-specific threshold and separation from the best distinct canonical alternative both pass. Exact alias resolution is independent of a fuzzy threshold. An ambiguity or budget exhaustion returns candidates/diagnostics rather than changing the value. Determine thresholds from held-out labeled inputs; record the false-coercion rate, coverage, and abstention rate. Similarity scores are not confidence probabilities.
6. Preserve every original input and its result even when several inputs resolve to the same canonical value. A separate accepted-values projection may retain the existing sorted/deduplicated output. Formatting/enrichment must retain unresolved or ambiguous source values in the field when allowed, otherwise in an explicit loss/provenance report; never silently discard them. Keep missing affiliation defaulting separate from a supplied affiliation that failed to resolve. Organization lookup should traverse all supported hierarchy depths with path/type evidence and distinguish identical labels in different branches.
7. New coercion treats input as literal text on both native and alloc/WASM builds; ordinary metadata must not execute `^`, `$`, `!`, or other pattern syntax. Phase 1A explicitly removed Nucleo and the legacy public wrapper after every in-tree caller migrated, rather than retaining a second search behavior with divergent portable semantics. The committed fixtures and literal-pattern regression publish that compatibility decision.
8. Prepare a vocabulary once per batch, indexing exact canonical values and aliases before bounded fuzzy scoring. Key reusable prepared data by vocabulary content/revision and policy version, without a host-only global cache. Bound entries, aliases, per-input work, total batch work, and returned candidates. Candidate pruning must preserve measured recall and report incomplete searches; never declare a unique automatic match from a truncated candidate search.

## Mathematical contracts to freeze first

1. **Input units:** use Unicode scalar values for character algorithms, never UTF-8 byte offsets. Raw matching is case-sensitive and does not normalize implicitly. Explicit preprocessing modes are raw, lowercase, full locale-independent case folding, NFC, and NFKC; modes are not composable. Do not equate lowercase with full Unicode case folding. Keep raw as the general API default because normalization changes scalar-level distances and NFKC can erase meaningful compatibility distinctions. Recommend NFC as an opt-in for human-language matching that should equate canonically equivalent encodings, and use NFKC only under an explicit compatibility policy. Preserve punctuation and diacritics unless the chosen policy says otherwise.
2. **Scores versus distances:** expose integer edit distances separately from normalized similarities. Unit Levenshtein similarity is `1 - d / max(lengths)` with empty/empty defined as 1. Never apply the slide's generic `1/d` at zero or assume `1-d` is normalized. Only methods with proven metric properties may drive metric-tree pruning.
3. **Empty/missing data:** primitive exact/string/set matching uses empty/empty = 1 and one-empty = 0 where mathematically applicable. Missing research fields are unavailable evidence, not empty strings or perfect matches. Zero-norm cosine and zero-weight TF-IDF return an explicit undefined-score error. Empty corpus, invalid thresholds, zero n-gram width, unequal vector dimensions, and non-finite numbers are typed errors.
4. **Sets and token sequences:** set methods deduplicate; Monge-Elkan keeps a documented token sequence policy. N-grams operate on scalars with explicit padding; an unpadded input shorter than n yields no grams. Boundary markers must not collide with literal input. Prefix/suffix comparison uses a positive requested scalar count and rejects inputs shorter than it.
5. **OSA versus Damerau-Levenshtein:** implement and test independently. Include `CA` versus `ABC` (OSA 3, unrestricted distance 2). The slide recurrence must not be advertised as full Damerau-Levenshtein. [strsim documentation](https://docs.rs/strsim/0.11.1/strsim/) distinguishes these variants and can supply a differential test oracle after compatibility review.
6. **Jaro/Winkler:** clamp the search window at zero; handle zero matches; count transpositions as half the mismatches between matched subsequences. For the conventional Winkler variant, freeze a maximum prefix of four, scale 0.1, and an explicit boost threshold (proposed 0.7, boost only above it). Page 16 instead shows an uncapped prefix and a long-string boost. Do not reproduce scores above 1 or silently clamp them; keep slide compatibility gated until a bounded definition is specified.
7. **Extended Jaccard:** page 32 counts all qualifying token pairs, allowing multiple matches per token. Its unmatched-token notation is ambiguous. Specify unmatched tokens as having no qualifying edge and test many-to-many cases. If a one-to-one matching variant is desired, name it separately and specify maximum-cardinality versus maximum-weight matching and deterministic tie-breaking.
8. **TF-IDF/Soft TF-IDF:** fix corpus document boundaries, count a term once per document for document frequency, freeze TF/IDF/log/smoothing choices, L2 normalization, unseen-token policy, threshold inclusivity, and corpus identity. Page 36 writes the right weight using the left token, even when a different right token is the best match. Resolve against [Cohen, Ravikumar, and Fienberg](https://www.cs.cmu.edu/~wcohen/postscript/kdd-2003-match-ws.pdf) and reference code before implementation. Best-match token reuse can defeat naive boundedness assumptions; do not silently clamp or label an unproven score as normalized. Preserve directional results or use a separately documented symmetric construction.
9. **Numeric/time:** absolute similarity is `max(0, 1 - abs(a-b)/cutoff)` for a finite positive cutoff. Percentage comparison uses `100 * abs(a-b)/max(abs(a),abs(b))`, with both zero treated as equal; guard overflow. Dates use calendar-day differences, and ages require a caller-supplied reference date. Special date-error scores are policies, not inferred truth.
10. **Phonetics/alignment:** choose Soundex vowel/H/W handling explicitly; the slide is a simplified rule order. Cologne requires umlaut/eszett and initial-vowel decisions. Double Metaphone returns primary and alternate encodings. Alignment methods need match/mismatch scores, gap-open/extension costs, local versus global behavior, and raw-score/normalization decisions before they have a stable API.

## Rust design and resource limits

Prefer small pure functions over a generic matching framework. Borrow inputs; use explicit configuration only for methods that require it. Proposed types are `SimilarityError`, bounded `SimilarityScore` for proven [0,1] methods, and separate raw/directional scores for other methods. Keep distance, score, algorithm/variant, preprocessing, and corpus metadata distinguishable in results. Never serialize NaN or infinity.

Use two-row Levenshtein with O(mn) time and O(min(m,n)) auxiliary DP space; Unicode scalar conversion may add O(m+n) storage. OSA needs sufficient previous-row state; unrestricted Damerau requires its own last-occurrence bookkeeping. Token-set operations should use stable sorted sets or deterministic output ordering. Cosine uses stable finite arithmetic; do not let square roots/logarithms accidentally introduce a host-only dependency in no_std builds. Evaluate existing portable math support before adding a dependency.

Set caller-configurable, enforced limits before allocating: proposed defaults are 4,096 scalars per string, 4,000,000 DP cells/work units, 256 tokens per hybrid input, 65,536 token pairs, and a shared cumulative budget for nested token comparisons. Limits are provisional until benchmarked. Reject over-budget work explicitly; never truncate inputs silently. Full-matrix algorithms need a separate byte budget and checked dimension multiplication. Corpus construction must bound document count, token count, vocabulary size, and retained bytes, with deterministic errors.

Evaluate `strsim` as a test oracle or implementation dependency only after checking Unicode semantics, variant fidelity, license, MSRV, dependency cost, and alloc/WASM support. It is not selected as a production dependency by this plan. Basic methods should not require external services or model downloads.

### Phase 1B: post-migration regression hardening

Phase 1B treats the Nucleo replacement as a semantic migration. Vocabulary resolution is a literal controlled-data canonicalizer. It does not preserve Nucleo's search language: `^`, `$`, `!`, quotes, spaces, and punctuation have no operator meaning unless a vocabulary-specific normalization rule says otherwise. #### Compatibility corpus and release measurements

Build one versioned old-versus-new corpus from historical tests, repository fixtures, declared aliases, approved real-world examples, generated one- and two-edit mistakes, abbreviations, punctuation and whitespace variants, Unicode variants, near neighbors, hard negatives, and deliberate ambiguity. All cases must be redistributable and non-sensitive. Each case records a stable ID, vocabulary kind, input, expected canonical value or abstention, source class, expected strict and relaxed outcomes, calibration or held-out partition, compatibility classification, and rationale where the expected result is ambiguous or intentionally different from the old resolver.

Classify each differential result as unchanged, newly rejected, newly accepted, changed canonical, newly ambiguous, or resource-limited. Review every changed canonical and every old-accepted/new-rejected case. Raw Nucleo and portable similarity scores are not comparable and do not belong in compatibility assertions. A temporary dev-only harness may generate the historical baseline; the permanent fixture stores reviewed outcomes and does not keep `nucleo-matcher` in any runtime or development feature graph.

Keep calibration and held-out evaluation separate. Stratify each partition by vocabulary, input-length band, and positive, negative, or ambiguous class. All mutations of one base canonical term stay in the same partition. A threshold change prompted by held-out results requires a new versioned split; do not tune repeatedly against a fixed held-out set.

Strict automatic coercion may abstain aggressively and has a zero-known-false-canonicalization release target. Relaxed automatic coercion requires, for each vocabulary, at least 100 held-out cases that relaxed mode accepts, observed precision of at least 99%, exact correct/accepted counts, and a reported 95% Wilson interval. Protected hard negatives allow zero false acceptance regardless of aggregate precision. Report recall, abstention, ambiguity, and top-three candidate recall for both profiles. Any vocabulary that misses its target uses a recorded strict fallback even when the requested mode is relaxed, until that vocabulary is recalibrated.

Thresholds remain checked-in deterministic policy, separated by vocabulary and input-length band. Users select named policies and cannot override raw scores, edit-distance ceilings, or margins through CLI flags or environment variables. Every threshold or matching-policy change increments the policy revision and records corpus metric deltas plus changed-outcome snapshots.

#### Resolver and normalization contract

Exact canonical, declared alias, typed identifier, and unique normalized matches precede fuzzy scoring. Short acronyms canonicalize only when declared as aliases. Generated acronyms may appear as low-authority relaxed candidates but cannot change metadata until promoted to a reviewed alias. Exact or normalized keys shared by distinct canonical entries are ambiguous. A normalized unique identifier such as one ROR ID assigned to more than one canonical entry makes the authoritative vocabulary asset invalid and fails resolver preparation.

Use NFC plus full locale-independent Unicode case folding for organization, partner, and sponsor comparison keys. Use NFKC plus full case folding for keywords and technology. Typed identifiers retain identifier-specific normalization. Canonical output always comes from the declared vocabulary entry. Organization-like names may normalize commas and periods used as legal-name formatting; keywords map whitespace and underscores to their hyphen convention. Technology punctuation remains significant, so `C++`, `C#`, `.NET`, versions, and similar forms change only through explicit aliases. Any normalization collision across canonical entries abstains as ambiguous.

Score keywords and technology with a calibrated character-edit method and organization-like names with calibrated token/name methods, retaining method and variant in every result. Method changes are policy changes and require the same revision and corpus review as threshold changes. If profiling confirms duplicate OSA distance and normalized-score passes, combine them without changing results.

Each input has an independent work budget. Preflight complete batch work before fuzzy scoring. A batch that exceeds its ceiling performs deterministic exact, alias, identifier, and normalized lookup, then marks the fuzzy stage resource-limited for the whole batch; it never accepts a partial prefix. Reordering inputs cannot change accepted canonical results. Native cached, native uncached, alloc-only, and WASM resolution must produce identical outcomes, candidates, ordering, limits, and revisions.

Keep at most three distinct canonical candidates per result. Collapse aliases belonging to the same entry, then order by score, canonical value, and stable locator. Stable deduplication applies after canonicalizing scalar keyword, technology, and partner lists. Contact organization and affiliation are scalar fields. Funder records remain distinct even when canonicalized names become equal because their other evidence may differ. Reports retain every source resolution, including inputs that converge on one canonical scalar value.

|---|---|---|---|
| Already canonical | none | none | none |
| Exact alias, identifier, unique normalized, or strict-fuzzy canonical change | none | Info | Info |
| Relaxed-only canonical change | none | none | Warning |
| Ambiguous, including exact/normalized cross-canonical collisions | none | Warning | Warning |
| Resource-limited fuzzy evaluation | none | Warning | Warning |
| Unmatched or invalid | none | none | none; ordinary field/schema validation still applies |

Info findings are non-failing and follow existing informational visibility. Warnings are visible by default, participate in failure counts, and produce the normal nonzero check result. Use stable rule IDs `vocabulary.canonical-change`, `vocabulary.relaxed-match`, `vocabulary.ambiguous`, and `vocabulary.resource-limited`. The structured payload records the underlying exact, alias, identifier, normalization, strict, or relaxed evidence without multiplying rule IDs.

Keep human messages concise. Accepted findings name the declared replacement; ambiguity names the bounded candidates; resource warnings say the selected evaluation did not complete. Numeric scores stay out of normal human output and appear only in verbose or structured output, labeled as similarity rather than confidence.

Add an optional versioned vocabulary-advisory payload to `Check` and inference references. Omit it for all existing checks and from serialization when absent. The payload contains original value, source locator, vocabulary kind and revision, policy revision, effective mode, outcome, completeness, canonical replacement when accepted, up to three candidates, stable candidate locators, method and variant, score, edit distance where applicable, runner-up margin, and evidence kind. Advisory contents participate in finding fingerprints. Validate and bound payloads received across external service boundaries.

Update the ACORN book's `docs/src/cli-reference/commands/check.md` page with the `--fuzzy off|strict|relaxed` option, relaxed default, six covered RAD surfaces, severity and exit-status behavior, stable rule IDs, deterministic fixes, and the distinction between normal human output and structured advisory details. Include examples for disabling vocabulary checks, selecting strict mode, and inspecting relaxed warnings in JSON. Keep generated CLI help and the book page consistent, and run `make book` after the documentation update.

#### Deterministic fixes and inference boundary

Accepted Info and Warning findings carry the declared canonical value as a deterministic `safe-automatic` fix. The complete human recommendation also appears in `Check.message`; fix code must use the structured payload and never parse replacement data from prose. Ambiguous and resource-limited findings have no automatic fix.

Before applying a vocabulary fix, require all of the following: the source fingerprint matches; the original value remains at the locator; vocabulary and policy revisions match; the current resolver still selects the same canonical value; and the result remains complete and unambiguous. A failure marks the proposal stale and requires a new check. Applying several fixes stably deduplicates scalar vocabulary lists and shows convergence in the preview and audit record. It does not merge structured funder records.

Pass canonical-change Info findings and all three Warning types into the existing inference pipeline when fix suggestion processing is enabled, independent of ordinary human visibility. Inference may explain or group accepted deterministic replacements but cannot alter them. Ambiguity candidates and resource failures are context only. Inference cannot select an ambiguous candidate, fabricate a replacement, or bypass deterministic acceptance gates. Any inferred candidate must return through declared canonical, alias, or identifier validation and the selected deterministic policy before automatic application. Interactive ambiguity selection remains outside this phase.

#### Persistent prepared-vocabulary cache

Native `std` builds cache prepared embedded-vocabulary state beneath the standard ACORN cache root in a dedicated `standards/vocabulary` namespace. The cache stores derived canonical terms, aliases, identifiers, indexes, and version metadata. It never stores authored input, provider evidence, advisory results, scores, messages, inference content, or fix history. Alloc-only and WASM builds remain cacheless and prepare the same immutable resolver in memory.

Use bounded, disposable, versioned JSON. Key each entry by vocabulary kind, vocabulary content digest and revision, policy revision, cache-schema version, and Unicode case-mapping/normalization data version. Validate keys before use. Write a temporary sibling and replace atomically. Missing, stale, corrupt, or unknown-version entries are cache misses and rebuild automatically; a cache-write failure falls back to an in-memory resolver without changing check results. Do not use time-based expiration. Concurrent processes may race only to publish equivalent immutable entries.

The existing global `--clear-cache` operation clears this namespace together with other ACORN caches, reports what it removed, and then continues the requested command. A failure to clear safely stops command execution. Cache clearing never removes audit logs.

#### Applied-change audit log

Every frontend that applies a vocabulary replacement uses one audit mechanism: format, gather, check/fix execution, TUI fix application, and service-driven fix execution. Preview, check-only, inference-only, unchanged, failed-before-mutation, and fully rolled-back operations do not create a report. If at least one change is applied, write one combined invocation report beneath the standard ACORN application-data log root, for example `logs/vocabulary/<timestamp>-<run-id>.json`. Do not embed the report into RAD metadata.

The report includes source URIs and content fingerprints, effective mode, original and canonical values, per-input outcomes, candidates, evidence, vocabulary and policy revisions, applied/unchanged/failed/rolled-back source status, and deduplication effects. It does not store full document snapshots or provider credentials. Multi-file operations allow audited partial success: successful files remain changed, every applied source appears in the report, and any failed source still causes command failure.

Use restrictive user-only permissions where the platform supports them. Bound fields and report size, reject traversal in source-derived identifiers, avoid symlink escapes, serialize deterministically, and publish atomically. Retain the latest 1,000 vocabulary audit reports. `--clear-cache` does not remove them.

Add a global `--clear-logs` flag beside `--clear-cache`. It clears only ACORN-managed application-log namespaces beneath the resolved log root, reports counts, and then continues the requested command, allowing that command to create a new report. Missing log directories are successful no-ops. Unsafe or failed clearing stops execution and never reaches outside the ACORN log root.

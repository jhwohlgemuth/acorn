# Reviewer summary prompt — beta architecture

## Current contract, November 12, 2026

The published [BETA] Sponsor Highlights Review app has Standard license designation. Five app-facing review flows use SharePoint; the app has no direct AI model data source. [BETA] Request Reviewer Summary (`0ddfbf82-88c1-499f-93af-c3d33718ff22`) retains the content/summary interface, checks reviewer-group membership, and writes a request to restricted SharePoint queue `442cdec0-52b9-4f24-97b6-092961312c41`. [BETA] Generate Reviewer Summary (`e731badd-095c-49bf-806a-c0b6b5132bd5`) runs asynchronously on the owner’s plan and invokes existing prompt `4d199cce-5673-4675-9046-d70eeb69b188`. This replaces the direct app-to-AI flow described in the historical evidence below. Participant licensing acceptance remains pending.

Both the ledger and Report View generate after a confirmed approved Save, including an unchanged exact reread. Failed and non-approved saves do not generate. Suggestions are never applied automatically. Reviewers may add up to 2,000 characters of context and regenerate; the combined prompt input is bounded at 12,000 characters, and output at 1,200. The ledger includes original status health/reason, significance, evidence, risk, and reporting bounds as well as activity details. The report view includes its original-source comparison details. Context travels to the prompt and is stored in the restricted queue, but is absent from the immutable submission and review-save payload. Selection changes clear or scope context so it is not reused for another item.

Use Suggestion changes only the local review text and requires a subsequent Save. In Report View, applying text returns the decision to Unresolved; select Approve again when the revised wording is acceptable. Error responses preserve the saved review and allow a retry or manual summary.

Owner-context automatic generation and context-assisted regeneration passed in both published views. The exact request IDs and limitations are recorded in [beta verification](../beta-repair/verification.md). No premium license was purchased or assigned. The observed designation does not replace an intended-user launch/read/save test or a tenant licensing decision.

## Historical direct-flow evidence

`Summarize Reviewer Submission TEST ONLY` is a custom AI Builder prompt in the `Wohlgemuth, Jason` Power Platform environment. It uses GPT-4.1 mini and one text input named `text`. `Summarize Reviewer Item TEST ONLY` is an instant flow in the same environment with a Power Apps (V2) `content` input, a `Run a prompt` action, and a `summary` text response. The flow ID is `0ddfbf82-88c1-499f-93af-c3d33718ff22`. Trigger, prompt, and response run-history data have secure inputs/outputs enabled.

The prompt asks for a proposed report summary in two or three sentences and at most 1,200 characters, using only facts in the submission. It must preserve important names, dates, results, and uncertainty; omit contact details and instruction text; and state when content is too sparse. The app supplies the selected item's original summary, supporting content, and submitted details. It does not send the submitter address, receipt ID, or review decision to the prompt. The app rejects input over 12,000 characters and empty or overlong output. The reviewer must inspect and explicitly apply or discard the suggestion. Generating a suggestion never changes a decision or saves a draft.

On November 8, 2026 the prompt saved successfully in AI hub. A synthetic Project Atlas sample stated that 12 records were tested, two defects were found, a retest was scheduled, and no production rollout was approved. The generated result preserved all four facts without inventing an approval. Prompt builder displayed 0.2 Copilot credits for this test.

At the November 8 checkpoint, the TEST ONLY reviewer draft was saved and unpublished with a Generate button calling the direct flow. Studio reports no formula errors. From the local review fixture, a synthetic general-update item generated a suggestion in the app. Flow run `08584074358250576005958823489CU26` succeeded in 3 seconds; its `Run a prompt` action succeeded in 3.3 seconds and the response succeeded. [The synthetic preview](ai-summary-preview.png) shows the suggestion and explicit apply/discard controls. Discard left the fixture summary and unresolved decision unchanged. A second synthetic generation followed by Use suggestion changed only the local fixture summary and kept the decision unresolved.

On November 8, 2026, PA-36C added the same bounded interaction to `ReviewLedgerLiveScreen` through the accepted PA-36B item-read contract. The app constructs the prompt input from the decoded original entry only: `summary`, the ordered `items`, `category`, `state`, `eventType`, and `timestamp`. It does not send the outer `projectId`, `submissionId`, `submittedAt`, submitter object, source or item ETag, saved draft, validation state, or review decision. Switching items clears the prior suggestion before the next item read, and a returned suggestion is shown only when its captured batch/item key still matches the current selection.

The live two-item TEST ONLY batch generated this factual suggestion for the selected root fixture: `PA36A TEST ONLY root` was described as in-progress software work with the synthetic reviewer fixture and its November 8 timestamp. Selecting the correction item immediately cleared the applied result. A separate Project Atlas status fixture generated a bounded status summary that retained the on-track state, accessibility-check evidence, and unchanged milestone. App checker reported zero formula issues after the binding was saved.

The app rejects empty input and input over 12,000 characters before calling the flow, rejects empty or over-1,200-character responses, and exposes bounded stale-selection and service-error states. These branches are present in the checker-clean formulas; the successful live service path was exercised, but no external capacity failure was injected. ## November 12 context-assisted regeneration

The published TEST ONLY live ledger keeps approved-save automatic generation and adds an optional 2,000-character context input after the first generation attempt. Regenerate summary appends the typed facts to the same content input as `Additional reviewer-provided context:`. This extends the original-entry-only input contract above; the existing prompt and flow are unchanged. Context is held locally under the selected batch/item key, is included in AI requests, and is not stored in the review save payload. The combined input still cannot exceed 12,000 characters. The context field is disabled during generation, and existing item-key response checks remain in force. Use suggestion explicitly copies the new result into the local draft and marks it unsaved. Regenerating alone preserves existing local review text and the saved decision.

## Repair

A prior-file read must succeed with content, or fail with an explicit numeric 404, before the publish branch can execute. Failed, timed-out, skipped, missing-output, and non-404 reads otherwise stop before writing. Missing-file creation uses `overwrite=false`, protecting a file created between the read and creation attempt. Existing-file updates retain serialized execution and use `overwrite=true`.

After a write failure or timeout, the flow reads the file again. Only a successful read with exactly the expected Base64 bytes emits an export receipt. A failed read or different content terminates as `LogbookOutcomeUnresolved`. It never claims that the old file survived a write attempt and never rolls back over a later snapshot. All connector retries remain disabled. A later serialized rebuild reads the immutable receipt list again.

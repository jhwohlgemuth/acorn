ART DIRECTION
Use pale ceramic and stone bodies, broad silhouettes, modest bevels, and a
consistent low graphite pedestal. Scientific pieces use teal accents; places
use characteristic materials and terrain colors. Preserve negative space under
the arch, between bridge towers, and around the accelerator ring.

The DOE campus is an invented category symbol, not an architectural depiction
of a particular national laboratory. Use a text identifier in the interface to
name the actual organization. A later institution-specific collection can use
verified facility references. The user-facility ring is one visual example,
not a claim that every user facility is an accelerator.

ACORN concepts describe records and relationships. Place a concept at a site
only when the user or source data explicitly links it to that site. Dataset,
software, publication and funding objects should otherwise appear in the
object palette or selected-location details, without invented coordinates.
Yellowstone and Kennedy Space Center are composite symbols for their locations;
the artwork is not an accurate survey of their individual structures.

GEOSPATIAL PAGE DESIGN
Add an Objects palette with Laboratories, U.S. landmarks, Wonders and Research
concepts categories. Each item has a preview, name and placement action.
Organization-derived objects retain the organization's existing selection and
details behavior. Curated landmarks have their own identity and location.
Keep layer controls for research objects and decorative landmarks independent.

Suggested interaction:
1. Choose a category and object.
2. For an organization, assign its visual to an existing location. For a curated
   landmark, use a verified location. For a custom object, choose a map position
   or enter coordinates, with a visible placement preview.
3. Select the placed object to view its label, source and related records;
   expose size, heading, visibility and remove actions in a compact inspector.
4. Keep the organization table and a keyboard-accessible object list available.

At global zoom, prefer markers or clusters. At regional zoom, reveal selected
or sparse miniature silhouettes. At close zoom, show the detailed miniature.
Selection uses an outline/double ring and a readable label, not color alone.
Research marker status retains the current green/amber meaning; model materials
must not silently redefine those colors. A shared-site project count belongs
in a separate badge. Avoid persistent labels competing across the whole globe.

The globe insets illustrate scale and hierarchy. Their locations, buildings,
territory shapes and floating placement are not exact implementation targets.
Real placement should anchor the model's bottom center to the local surface,
orient upright along the local surface normal, and apply a small controlled
clearance to avoid clipping. Screen-space labels remain upright independently.

MODEL HANDOFF
Produce one editable source model and one glTF/GLB export per object, with an
explicit scale, documented axis convention, and bottom-center placement pivot.
Keep the pedestal and body separate so ownership and selection treatments can
change without recoloring the whole object. Do not bake names or counts into
the mesh: use interface labels for accessible, localized text.

Start with material colors and very limited textures; reduce repeated facade
detail in distant variants. Thicken small features such as bridge cables,
minarets, statue arms and sensor masts. Test silhouettes at small screen sizes
and oblique angles before committing to fine geometry. Performance budgets
must be measured in the actual Cesium scene; these renders establish no tested
polygon, memory or frame-rate target.

Cesium ModelGraphics supports glTF models, minimumPixelSize, maximumScale,
heightReference and distanceDisplayCondition. Pair any minimum screen size with
a maximum scale and distance visibility policy so a distant miniature does not
grow enough to obscure an entire region. Bundle model assets locally to fit
the existing offline basemap option. Terrain-dependent behavior needs separate
verification when optional online terrain is enabled.
Reference: https://cesium.com/learn/cesiumjs/ref-doc/ModelGraphics.html

CURRENT INTEGRATION CONSTRAINT
The inspected MapView renders point entities from organization markers; the
bridge currently validates marker IDs as ROR URLs. Generic landmarks and game
tokens cannot simply be inserted into that collection. A future implementation
needs a distinct decorative-object collection and a separate game-state model,
with an explicit bridge design. No bridge or research schema was changed here.

RISK COLLECTION
Keep the game in a separate mode with its own territory ownership, counts and
selection. Use the same globe engine and placement conventions. Research dots,
project status colors and decorative landmarks should not become game state.

Choose one piece family per match. Use colored bases plus persistent faction
symbols in territory badges; a symbol hidden underneath a figure is insufficient.
Show white double rings for selection and a distinct target outline for legal
destinations. Movement/attack arcs appear only during the relevant interaction.
Disable decorative motion when reduced motion is requested.

At close zoom, denomination models can represent an army total (12 = one
artillery + two infantry). At distant zoom, collapse that group to a faction
marker and authoritative numeric total. The concept sheet's globe inset is a
composition study: its displayed figures and counts are not a consistent game
position. Production rendering must derive both from the same game state.

Game territories require an explicit board layout and adjacency model; country
borders are not automatically Risk territories. Place a territory's token at a
chosen interior anchor so it does not fall into an ocean or outside a concave
territory. Handle overlap, globe-horizon occlusion and cross-dateline arcs in
the game implementation. The board's rules and territory dataset remain outside
this object-design deliverable.

VISUAL REVIEW
Reviewed all four generated sheets for category coverage, legible labels,
recognizable silhouettes and a coherent material/base family. All requested
categories are represented. The geographic insets are schematic, and the sheets
do not establish model topology, actual lighting behavior, accessibility or
runtime performance. Those checks belong to the future GLB implementation.

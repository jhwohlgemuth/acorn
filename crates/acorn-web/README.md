# RAD Workspace

RAD Workspace (RAD: Research Activity Data) is a local Dioxus workspace for nine ACORN operations, loaded Research Activities, and organization locations. It inherits the workspace version and links `acorn-wasm` into the UI's single WASM payload. Its dependency graph excludes `acorn-lib` and `acorn-host`. Desktop/Tauri delivery remains planned.

## Develop and validate

```sh
make web-setup       # Optional explicit setup: pinned Dioxus CLI and WASM target
make web-dev         # Dioxus :8080 and Vite map Fast Refresh :8083
make web-check       # Package formatting, native/WASM checks and strict Clippy
make web-test        # Packaging, native projections, real WASM, effects and assets
make web-build       # Static release and single-WASM/export verification
make web-preview     # Serve release assets on loopback :8080
npm --prefix crates/acorn-web/geospatial test
node crates/acorn-web/scripts/parity-smoke.mjs
```

Prerequisites: rustup-managed Rust/Cargo, Python 3, Node.js 22.17+ and `wasm-pack` (tested with 0.15.0). Browser Rust commands use the active rustup toolchain, including when Homebrew Rust appears first on `PATH`. GitLab installs checksum-verified Node.js 22.23.5 for `build-web`. `web-test` installs the map test dependencies before running them. `web-map`, included in dev/release builds, runs `npm ci --ignore-scripts` against the pinned map lockfile. Install browser-test dependencies with `npm ci --prefix crates/acorn-web` and `crates/acorn-web/node_modules/.bin/playwright install chromium` once. The parity script accepts an optional public-directory path, screenshot-output directory and base prefix; defaults are `target/dx/acorn-web/release/web/public` and `target/abw-parity`.

`WEB_PORT=8084` changes the Dioxus or preview port; Vite uses loopback port 8083. The coordinator passes the selected frontend origin to Vite; CORS permits only that port on `127.0.0.1` and `localhost`. Both names work when opening the development frontend. For standalone `npm run dev` with a custom frontend port, set `ACORN_WEB_DEV_ORIGIN=http://127.0.0.1:<port>`. `web-dev` and `web-build` automatically run `web-setup` if the local Dioxus executable is missing (including after cleaning `target`). The first run may take longer while Cargo installs the pinned CLI. `DIOXUS=/path/to/dx` overrides `target/tools/dioxus/bin/dx`; custom executables are checked and never replaced automatically. The development coordinator uses plain Dioxus logging, waits for Vite readiness, stops both process groups on exit and restores terminal settings; a port conflict fails without terminating another server. This coordinator currently targets POSIX hosts. Compatible map TSX/CSS edits use Vite Fast Refresh/HMR; `main.tsx`, dependency/config changes and Rust changes can require a reload/rebuild. Initial Vite dependency optimization may reload once and clear the in-memory session. `node crates/acorn-web/scripts/dev-smoke.mjs http://127.0.0.1:8084` checks map refresh with temporary source edits restored in `finally`; run it only with no concurrent map editor. Dioxus owns the surrounding RSX/CSS/static watcher. Production embeds local static assets without either development client.

Cargo stages canonical artwork, the unchanged WebMCP adapter and the verified skill bundle before asset macros expand. Generated staging is ignored. Use `make web-map web-prepare` before a direct `dx` build; ordinary Cargo checks do not build the JavaScript map or editor. Both use directory assets, so native workspace lint, test and coverage jobs can compile from a clean checkout without Node or generated JavaScript bundles. Browser builds still require those bundles. Release builds use the `web-release` profile and `--debug-symbols false` to avoid the Dioxus 0.7.3/Binaryen DWARF failure. The package check rejects a second WASM payload, missing operation exports or retained DWARF sections. The crate has `publish = false`; its distribution is the website.

## Local workspace and tools

Home provides the ACORN banner with a RAD Workspace subtitle, adjacent tour and **Try Sample Data** actions, Skill entry, paired file/folder and drop loaders, and expandable remote loading. The empty layout fits desktop, portrait and landscape viewports; expanded content can scroll. The sidebar starts with its directional collapse/expand control and compact navigation, without an icon header. A compact Portfolio shortcut always shows activity and file counts, including `0 activities · 0 files` for an empty session. Its tooltip clarifies validation and the selected file; the collapsed sidebar keeps both counts. The RAD footnote and fixed bottom credit appear only on Home. The browser tab uses the canonical brown ACORN SVG favicon. The sample action explicitly loads and validates three illustrative RAD examples, then opens Portfolio. **Use example** sits in each Input header, shares the Home sample-action styling, and only fills its editor. ACRE 2.0.0 is a separate CLI configuration download, not a browser validation tool.

Files remain in tab memory. The loader accepts `.json`, `.yaml`, `.yml`, `.md` and `.txt`, with 500 files, 20 path segments, 256 KiB per file and 16 MiB total. It rejects invalid UTF-8, unsafe paths and unsupported files, sorts relative paths, reports skipped entries and preserves the prior session on cancellation or total failure. Folder selection is capability-detected; unsupported browsers retain single-file loading. The expandable tree selects text without running a tool. Portfolio validates loaded JSON only when requested and derives filters, sortable records, deduplicated metrics and distribution bars from successful portable validation results. Replacing or clearing the session removes stale validation.

Public GitHub and GitLab repositories, folders and file web URLs can be loaded from Home. GitHub also accepts `owner/repo`; GitLab supports nested groups and public self-hosted instances with CORS enabled. An optional branch, tag or commit is resolved to an immutable commit before downloading. Enter slash-containing branch names explicitly. Requests omit credentials and reject redirects; no tokens are collected. Loads are cancellable, limited to 10,000 listing entries and the same file/session limits, and replace the session only after success. API limits and servers without browser CORS support show an error while preserving the session. GitHub currently requires the repository recursive listing to fit the listing limit, even for a folder or file URL. Both remote input fields offer native autocomplete from the 20 most recent unique submitted values in local storage. Valid repository inputs are remembered even when a download fails or is cancelled; rejected URLs and blank revisions are omitted. **Clear suggestions** removes this history. Unavailable or full browser storage does not block loading.

Every tool offers a compact **Load content** control. Open it to **Choose file** or **From URL → Load URL**; connection details stay in **Link tips**. The tray closes after a successful load and returns focus to the editor. Close it with **×** or Escape to cancel a pending download and return to the launcher. On Home, choose **Open file or folder → URL** to load a single file into the workspace. Direct HTTPS URLs (including query parameters) and GitHub/GitLab file links are supported; repository web links are converted to raw-file URLs. Downloads omit credentials and referrers, follow browser-approved redirects, enforce the destination tool’s UTF-8 byte limit while streaming, and time out after 30 seconds. Cancel, failed downloads, oversized responses and invalid UTF-8 preserve the existing content. Navigating away or selecting a local file cancels pending downloads. Servers must permit cross-origin browser access (CORS); otherwise download the file locally and choose it from disk. URL inputs are not saved to browser history by the app. Loading supplies content without automatically running validation or analysis.

The shared details drawer opens from Portfolio activities, loaded-file names, diagnostic Inspect buttons, and organization selections on the map or table. Overview shows metadata, linked identifiers, field values and surrounding JSON, or related activities. Source provides a read-only CodeMirror preview with nested folding, copying and exact-text download. Checks reuses existing validation results without running new checks. The panel starts at 480px, supports pointer and keyboard resizing, fills narrow screens, and uses a modal dialog with Escape, focus return, keyboard tab navigation and reduced-motion support. Previewing preserves the current editor; “Open in Research Activity” explicitly loads the previewed source for editing.

CodeMirror 6 provides editable syntax highlighting, line numbers, bracket matching, undo/redo and folding in all code inputs. JSON (including JSON-LD), YAML, XML, JavaScript/JSONC and Markdown use language-aware fold regions. Click gutter arrows or use **Fold all** / **Expand all**. Fold all collapses every nested foldable block, so opening a parent leaves its children folded; keyboard shortcuts are Ctrl+Shift+[ / ] (Cmd+Alt+[ / ] on macOS) for the current region and Ctrl+Alt+[ / ] for all regions. Plain text and expression inputs remain editable without artificial fold regions. Folded text remains part of validation, byte counts, selection and clipboard operations. Editing preserves folds and selection; replacing an example or file resets the editor's history and folds. Drag the bottom handle to resize an editor, or focus the handle and use Up/Down arrows. The chosen height survives edits and folding. Tab retains normal keyboard navigation. Editors are labeled for assistive technology and retain a native textarea fallback while the locally bundled editor loads. No CDN or remote editor service is used. `make web-prepare` bundles the pinned npm dependencies and their license notices; `node crates/acorn-web/scripts/editor-smoke.mjs` exercises resizing, folding, editing, undo, clipboard, incomplete JSON, large documents and both themes.

Locally bundled Prism highlights read-only code blocks, converted output, JSON results, diffs, identifiers, expressions, Skill source and workflow prompts in both themes. Content longer than 16,384 UTF-16 code units or with a line longer than 512 uses escaped plain text to bound synchronous highlighting work. Read-only blocks show logical line numbers that follow wrapping and scrolling; only visible numbers are rendered. Inline snippets remain unnumbered. Gutters are hidden from assistive technology and text selection. Highlighted and plain-text output escape HTML; copy and download preserve the original text. `node crates/acorn-web/scripts/syntax-smoke.mjs` checks read-only line alignment with classic scrollbars. Both browser checks run in `make web-test-pages`.

The [bundled examples](assets/examples/README.md) include three substantial valid RAD activities, an intentionally flawed validation workshop, all 12 PID kinds, longer research prose, and paired JSON snapshots for semantic diff. The Content diff example selects JSON Patch; key order and formatting alone do not count as semantic changes.

All nine tools use the existing `acorn-wasm` operations. Results show ordered diagnostics, crosswalk loss warnings, FAIR counts/findings, readability scores and configured thresholds, literal unified diffs or nested JSON Patch, identifier cards/candidates, and symbolic Big-O comparisons. The n/n² plot is explicitly an illustrative example, not a general evaluator or evidence of symbolic dominance. Every chart retains visible numeric/text equivalents. Missing/non-finite/off-scale values have explicit presentation. Readability scores and score markers are green when the associated threshold is met and amber when review is needed; Flesch Reading Ease uses a minimum and the other metrics use a maximum. The target direction and exact score remain visible. Raw JSON remains available.

Diagnostics are grouped by `CheckCategory`, with category icons and counts. Category headers expand or collapse their items with the mouse or keyboard; counts remain visible and sorting preserves collapsed groups. `CheckSeverity` controls the labeled color: error (red), warning (amber), suggestion (purple), and info (blue), with palettes for both themes. Paths, messages, and rule codes remain visible. Sorting controls offer original order, severity, field and rule within each category, with reversible direction. Crosswalk warnings sort by field or loss type; FAIR findings sort by severity, indicator or state. Sorting affects the displayed items only; exported results keep their original order. The service and WASM adapter retain category and severity in exported JSON. RAD validation includes schema errors, vocabulary advisories and all 41 local FAIR checks after successful parsing. Schema errors do not suppress advisories. FAIR checks use the analyzer's severity conversion; suggestions and information do not make a schema-valid document invalid. The FAIR assessment page retains separate evidence-state labels.

Purpose-specific actions (Validate, Convert, Assess FAIR, Analyze readability, Compare, Discover identifiers, and Inspect identifier) are explicit and focus the result heading. Invalid operations preserve editor text. Vocabulary matching uses mutually exclusive Off, Relaxed and Strict buttons. Diff format uses icon buttons for Unified diff and JSON Patch, with distinct selected colors. Code outputs, including raw JSON, diffs, identifiers, expressions and skill examples, have copy buttons that preserve their literal text and report clipboard success or failure. PID discovery results have combinable brand-colored type toggles with counts; All shows every type or hides all when everything is selected; filtering changes the visible list while exports retain the full discovery result. **Copy result** and **Download result** export the accepted converted content, unified diff, JSON Patch or JSON result with a safe filename/MIME. Adapter limits remain metadata 256 KiB, each diff side 128 KiB, readability/discovery 16 KiB, identifier 2 KiB and Big-O expression 256 bytes; results are capped at 256 KiB and displayed lists at 100 entries. Navigation seeds tools from the shared document; independent per-route drafts are not persisted.

Settings offers Dark/Light/System, actual file/activity/byte counts, clear-session and bundled skill identity. System preference changes apply until an explicit choice. Theme and file contents are not persisted; bucket input suggestions are saved locally. The drawer makes main content inert only while open and clears that state on desktop resize. Home/About reuse canonical banners and unchanged credited artwork; [asset notices](assets/NOTICE.md) record licenses and hashes. Driver.js 1.10.2 is bundled locally with teardown, reduced-motion and focus-return handling. External project links require a click. The read-only WebMCP adapter is unchanged; unsupported browsers retain all manual tools.

It presents source/revision/digests, raw/copy/archive actions, four copyable workflows and manual install/update/rollback/removal guidance. Workflow examples use category filters, tinted cards, icons and descriptions inspired by the OKF skill page. Only tracked authored files are packaged; add new resources to Git before packaging. Seven packaging tests cover deterministic bytes and stale/corrupt/unsafe inputs.

## Offline organization map

Geospatial lazy-loads the [pinned ROR 2.15 location index](assets/geospatial/ROR_PROVENANCE.md), extracts validated ROR references, deduplicates organizations and retains unresolved/locationless entries. The first country/coordinate-sorted location is used; this is not a headquarters inference. Discovery and valid ROR inspection results offer **View on map**, which adds the organization to the current tab’s map and focuses its coordinates. Added locations deduplicate with RAD references, retain their local ROR details, and do not alter RAD or increase activity reference counts. **Clear added locations** removes these additions; clearing the session also clears them. Unknown and locationless RORs remain inspectable in the table with an explicit explanation instead of a fabricated map point. Dioxus owns filters, selection, source counts, related activities and the semantic table. At most 1,000 matching markers/rows cross the bridge, with a visible truncation message. The route-local React/Resium island owns only the Cesium viewer. The initial view and Home button center on ORNL’s location in the bundled ROR index. The Cesium fullscreen control expands only the map and restores its embedded size on exit. A WebGL 2 capability failure leaves the selectable table available.

Cesium uses bundled NASA Black Marble (2016) imagery at tile levels 0–3, workers/widgets and ellipsoid terrain, with no ion token, remote imagery/terrain, geocoder or ROR request. The initial and Home views stay centered on ORNL at an altitude of 8,000 km. Releases carry upstream license notices and the Black Marble source/hash manifest. Four unused optional Cesium WASM decoders are excluded because this viewer exposes no 3D Tiles, KTX, splat or ZIP import. Enabling those features requires revisiting the asset contract.

Initial static budget (uncompressed / sum of per-file gzip bytes): map entry 5.75 MB / 1.43 MB; CSS 24 KB / 5.4 KB; workers 1.03 MB / 327 KB; widgets 515 KB / 429 KB; Natural Earth II tiles 476 KB / 470 KB; complete map graph about 11.95 MB / 5.32 MB. The Black Marble update adds 1.90 MB of local PNG tiles. ROR adds 22.28 MB / 4.96 MB and loads only on Geospatial. These are measured transfer/storage sizes, not browser memory budgets. Dataset regeneration from the pinned source hash is deterministic. Maximum-session performance and native-webview resource acceptance remain open.

## Application publishing lifecycle

`acorn-web` and `acorn-desktop` are application distributions. `packaging/applications.json` records both independently of the crates.io release list. Rust release commands live in `xtask/src/application_release/`. `make check-release-apps` runs `cargo xtask check-release-apps`, checks coverage, workspace version inheritance, `publish = false` and pending desktop work, and runs the Rust packaging/upload regression tests.

`make release-version VERSION=X.Y.Z` runs that application check before changing the workspace version, then updates dependency pins, `CITATION.cff` and `Cargo.lock` and verifies crate/version consistency. The browser package, UI version, archive name and embedded release metadata derive from the workspace version. After the version change reaches GitLab main, CI builds and publishes the matching browser ZIP and checksum. The command itself does not build or upload artifacts. Desktop remains an explicitly planned distribution until its native crate and packaging jobs exist; it has no artifact to release yet.

`make web-package` builds the browser, verifies the single WASM payload and nine operation exports, then writes `bin/acorn-web-v<VERSION>.zip` and its `.sha256` sidecar. Extract the ZIP and serve it over HTTP at the origin root. `release.json` inside the archive records the source revision, workspace version, file hashes and application publication states. Archive bytes are reproducible for identical inputs.

On merge requests and relevant default-branch changes, `build-web` checks, tests and packages the browser. On the existing default-branch `Cargo.toml` release trigger, it also runs `make web-publish`, using `CI_JOB_TOKEN` and `PKG_REGISTRY_URL`. Publication verifies the existing archive before uploading it to `acorn-web/v<VERSION>/` in the GitLab generic package registry. The release job waits for this build/upload and exposes ZIP and checksum links labeled **browser preview**. Existing identical remote bytes are accepted on retries; different bytes at the same URL are rejected. `make web-package` delegates to `cargo xtask package-web`; `make web-publish` delegates to `cargo xtask publish-web`. The latter performs a real upload and does not rebuild. GitHub Pages deployment is handled separately by the mirror workflow below.

The browser remains a preview while its documented acceptance and optimizer limits remain open. These registry URLs use the project's access policy; anonymous public access has not been established. The desktop crate does not yet exist. Its inventory entry remains `planned`, and no native download is advertised. ABW-11 must add the crate with workspace version inheritance and `publish = false`, move the inventory to `development`, and add native build checks and the Cargo packaging exclusion. ABW-23–30 must add signed native artifacts, release links and package-manager publication using the same immutable upload path, with actual public-download/signing evidence. Desktop packaging must retain the shared frontend version and digest and use identifiers distinct from the CLI.

For an existing browser build, run `cargo xtask package-web` and `cargo xtask verify-web` without rebuilding. Both accept `--output DIR`; packaging also accepts `--source DIR`. The CLI artifact uploader uses the same `cargo xtask upload-artifact FILE HTTPS_URL` implementation. Release checks, packaging, verification and HTTP uploads require no Python runtime.

## GitHub Pages mirror deployment

GitLab remains the source repository. Its enabled push mirror updates protected branches in `jhwohlgemuth/acorn`. `.github/workflows/acorn-web-pages.yml` deploys the browser preview after each mirrored push to `main`; it also supports a manual run on `main`. Other branches and forks cannot deploy through this workflow. Pages is a continuously updated preview of mirrored main, independent of the versioned GitLab ZIP releases.

The build reads the Pages `base_path`, runs `make check-release-apps`, builds with `make web-pages`, and runs `make web-test-pages` in Chromium before uploading only the generated public directory. The deploy job uses GitHub's Pages artifact and OIDC actions with `pages: write` and `id-token: write`; no GitLab token, personal deployment token, generated branch or additional backend is needed. Deployments are serialized so an active deployment is not interrupted by a later mirror push.

`web-pages` adds an identical `404.html` and a `.nojekyll` marker. A direct tool URL or refresh receives GitHub Pages' HTTP 404 response, then boots the application at that route. This preserves the URL and navigation; it does not change the server response to HTTP 200. The smoke test checks this behavior, stylesheet and image loading, local WASM execution, router links, and failed or unexpected network requests.

Reproduce the project-site build and browser check locally:

```sh
npm ci --prefix crates/acorn-web
# One-time browser installation; Linux CI also passes --with-deps.
crates/acorn-web/node_modules/.bin/playwright install --only-shell chromium
make web-pages WEB_BASE_PATH=/acorn
make web-test-pages WEB_BASE_PATH=/acorn
```

The GitHub repository is configured with Actions enabled, Pages' publishing source set to **GitHub Actions**, and the `github-pages` environment restricted to `main`. GitHub assigns the project site to the account's existing domain at `www.jasonwohlgemuth.com/acorn/`. The first hosted deployment is pending the workflow reaching the mirror. HTTPS enforcement must be enabled once GitHub provisions the site certificate; the setup API currently reports that the certificate does not exist yet. The GitLab mirror credential must be allowed to push workflow files (the `workflow` scope for a classic GitHub PAT). Keep workflow changes in GitLab so later mirroring does not overwrite GitHub-only edits. The first deployment requires this workflow and its supporting files to reach the mirror; the resulting live URL is recorded by the `github-pages` deployment. This setup does not change `acorn.ornl.gov` or publish desktop installers.

References: [GitHub custom Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Dioxus base-path configuration](https://dioxuslabs.com/learn/0.7/guides/tools/configure/).

Local hosting evidence: release builds and Chromium 158 smoke tests passed for `/acorn/` and an empty root base path. Both loaded assets, ran Research Activity validation, navigated within the configured prefix, and refreshed a direct Readability route through the Pages-style 404 response. The optimizer fallback was subsequently removed by the verified debug-symbol repair; this local hosting evidence does not claim a live GitHub deployment or a full browser matrix.

## Interface conventions

The shared shell and information pages follow the [OKF Plan Browser](https://www.jasonwohlgemuth.com/okf-plan-browser/) layout: 220px navigation, a theme-aware ACORN Home banner, 420px welcome column, paired load tiles, a sample action to the right of the tour button, and rounded cards with consistent section spacing. The published Home, Settings and About components were compared on November 12, 2026; the reference's direct `/home` HTTP route returned 404, so the app root and its published page assets supplied the comparison. ACORN accepts both `/` and `/home`.

ACORN retains its canonical artwork and green primary action (`#00662c`). Dark surfaces follow the [OKF browser theme](https://www.jasonwohlgemuth.com/okf-plan-browser/assets/index-BgyxskE8.css): canvas `#1f2229`, cards/sidebar `#252931`, borders `#3c414e`, and hover/selection `#2e333d`. Muted One Dark text (`#abb2bf`) accompanies One Dark Pro syntax colors in read-only code and editable CodeMirror blocks, with readable light-theme variants. ORNL green text selections work for single words and multiple lines; translucent active-line shading preserves selection visibility. Secondary text uses a muted gray (`#969daa`) that retains 4.5:1 contrast on interactive surfaces. Text and focus tokens have contrast checks in both themes. Research-specific screens use icon-led titles, unnumbered input/result sections, explicit validation actions, numeric portfolio metrics, selected-row and sort-direction indicators, and actionable empty filter states. The sidebar scrolls independently so all tools remain reachable on short screens. Emoji supplement labels; icon-only controls retain accessible names.

The parity smoke test covers Home action order, deep linking, sidebar labels, filter reset, all nine operations, theme selection, local imports, skill downloads, mobile reflow, 200% zoom and the map fallback. Its screenshots are review artifacts; automated checks alone do not establish pixel equivalence or institutional brand approval.

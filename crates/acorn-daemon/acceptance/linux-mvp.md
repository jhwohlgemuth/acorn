Native execution exposed three defects before the final report check. Read-access events from `acorn check` repeatedly requeued its watched input; the scheduler now accepts only create, modify, and remove events. Fourteen focused scheduler tests passed on macOS and Linux, including a read-versus-write watcher case. Managed Vale 3.9.4 rejected the downloaded proselint `LexicalIllusions` regex even when that rule was disabled in `.vale.ini`. During acceptance, a temporary source workaround removed that cached rule after managed sync; with the bad file restored before the test, runs 99/101/103 succeeded. Hunk review removed that workaround and the associated default rule change, so those successful check runs do not validate the current managed Vale path. The check runner's stdout also contained Vale sync progress before its JSON; a fixed global `--quiet` argument resolved this, with nine focused runner tests passing on macOS and Linux and native reports 125/127/130 passing `jq`. A Linux installer review also added literal dollar-path escaping and malformed-token rejection. Focused CLI tests (3), Linux installer tests (3), and package Clippy with warnings denied passed. These observations cover source-built local service behavior; signed bundles, SSH installation, and release upgrade acceptance belong to later phases.

Review repair, observed later on the same host: local CLI job control now connects through `/home/o9w/.local/share/acorn/daemon/rpc-18001.sock` instead of sending the token to the configured loopback port. The daemon directory was owned by `o9w` with mode 0700, and the socket and token were mode 0600. The rebuilt CLI listed both jobs while `acornd` was active; TCP `/healthz` still returned 204. A native fake occupied-port CLI test passed without connecting to the TCP listener. Repeated uninstall left the service inactive and removed both the unit and socket while retaining the protected token and `history.sqlite3`. Native Linux tests passed for 58 daemon, 17 server, and four focused CLI cases; affected-crate Clippy with warnings denied passed. A test fixture was updated to read the check input from argument three after the earlier global `--quiet` addition.

November 25 Hunk review reverted the Vale cleanup and default disabled-rule addition. A rebuilt native CLI ran `acorn --quiet check check.json --output json`: managed sync restored `LexicalIllusions.yml`, Vale 3.9.4 reported malformed `\\p{X}` in that rule, and the command exited 70. Checking the different `gather.txt` input produced the same rule-file error and exit 70. ACORN then updated its managed Vale pin to 3.28.1 and placed each managed version in its own cache directory. The current release archive passed its published SHA-256 checksum; ACORN's checksum parser was repaired to accept its six-character version. The rebuilt CLI downloaded Vale 3.28.1 into `/home/o9w/.cache/acorn/vale/3.28.1` and reran the same check with exit 0 and an empty check list. This validates direct check execution with the new pin; the earlier service check-job runs remain historical evidence from the temporary workaround.

# ACORN task recipes

## Decision tree

1. **Bug or feature?** Bug: read the adjacent `#[cfg(test)]` module, reproduce with a failing test, run focused tests. Feature: read the relevant schema or command module first and decide whether new fields need validation.
2. **Schema change?** Update `ResearchActivity` or the relevant struct in `crates/acorn-schema/src/`, add `#[validate(...)]` attributes and adjacent tests, and update `ARCHITECTURE.md` for major structural changes.
3. **CLI output?** Use `Label::*()` from `crates/acorn-host/src/terminal.rs`; test with `-vvv`.
4. **Network or external data?** Respect the `offline` flag, use `crates/acorn-lib/src/io/` utilities, and check `tests/fixtures/` for test data.

## Add a schema field

1. Edit the struct in `crates/acorn-schema/src/standard/rads/mod.rs` (or the relevant schema file).
2. Add validation and trimming:
   ```rust
   #[validate(length(min = 1, max = 100))]
   #[serde(deserialize_with = "string_trim")]
   pub new_field: String,
   ```
   Trimming helpers: `string_trim`, `vec_string_trim`, `option_string_trim`.
3. Add `#[validate(nested)]` to nested structs.
4. Add tests in the adjacent `#[cfg(test)]` module (`crates/acorn-schema/src/standard/rads/tests/` for the main schema).
5. Update commands that process the field. JSON Schema output is generated by `schemars`.

## Add a CLI command

1. Create `crates/acorn-cli/src/commands/<name>/mod.rs` with `pub fn run(...)` returning `color_eyre::eyre::Result<()>`.
2. Export it from `crates/acorn-cli/src/commands/mod.rs`.
3. Add the variant to `Commands` in `crates/acorn-cli/src/cli/mod.rs`; shared argument types live in `crates/acorn-cli/src/cli/arguments/`.
4. Add the dispatch arm in `crates/acorn-cli/src/main.rs`.
5. Run `make help-cli` to regenerate `CommandLineHelp.md`.

## Add analysis or checking logic

1. Portable analysis models and supplied-content checks belong in `crates/acorn-analysis/`; host-dependent analysis (Vale, GPU, fixes) lives in `crates/acorn-lib/src/analyzer/`.
2. `Check`, `CheckBatch`, `CheckCategory`, and `CheckSeverity` are defined in `acorn-analysis` and re-exported by `crates/acorn-lib/src/analyzer/mod.rs`; integrate results there.
3. Call it from `crates/acorn-cli/src/commands/check/mod.rs` and report with `Label::*()`.

## Export and PowerPoint

- OOXML manipulation: `crates/acorn-lib/src/io/powerpoint/` and `crates/acorn-lib/src/io/export/powerpoint.rs`.
- HTML template generation: `crates/acorn-cli/src/template/mod.rs`.
- Embedded assets (fonts, images, skills, styles): `crates/acorn-cli/assets/`, embedded via `rust-embed`.
- Test both PDF and PPTX targets.

## Tests

```bash
make test                                      # cargo nextest run
make test-all                                  # includes ignored tests
cargo nextest run --package acorn-lib analyzer # one module
cargo nextest run --package acorn-cli commands::check::tests::test_check_command
make test-ci                                   # lint + cargo test with and without default features
make cover                                     # tarpaulin coverage
```

Unit tests live in `#[cfg(test)]` modules using plain `#[test]` functions; cover the happy path and edge cases. Dev dependencies include `mockall`, `pretty_assertions`, and `similar-asserts`. Fixtures live under `tests/fixtures/` (for example `raid/`, `glob/`, `malformed-rad.json`).

## Debugging

- Test failure after refactoring: `cargo test --lib -- --nocapture`, with `RUST_BACKTRACE=1` for panics.
- Feature compilation errors: `cargo check --no-default-features` and `cargo check --all-features`.
- CLI parsing: check `crates/acorn-cli/src/cli/` (`mod.rs`, `parse.rs`, `arguments/`) and the clap derive attributes.
- Malformed export: check the template module, confirm assets exist in `crates/acorn-cli/assets/`, and compare with `tests/fixtures/export/`.

## Running from source

```bash
cargo run --bin acorn -- check /path/to/folder
cargo run --bin acorn -- export --format pdf path/to/file.json
```

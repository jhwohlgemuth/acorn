# Project manager trail

Goal: keep project developments, health, and risks connected to a reviewed research activity record.

<div class="acorn-growth emoji-growth four-stages" aria-label="Project manager trail from seed to tree"><span>Orient</span><span>Update</span><span>Review</span><span>Report</span></div>

1. Explore [RADS](../concepts/acorn.md) to see how a project record connects its identity, people, organizations, and work.
2. Read the [logbook overview](../packages/logbook-schema.md) to distinguish a dated activity from a status update. A status update records the main change, why it matters, project health, and any risk or dependency.
3. Follow the [intake review workflow](../cli-reference/commands/intake.md) to see how submitted updates are inspected and accepted before they enter the project record. Agree with the project team on who reviews each update.
4. Use the [report guide](../cli-reference/commands/report.md) to choose a reporting period and a PDF or PowerPoint output. Review the selected updates and report with the project team before sharing it.

Your finish line is a set of reviewed updates and a report for a defined period. A teammate can operate the commands while you coordinate the updates and review the report.

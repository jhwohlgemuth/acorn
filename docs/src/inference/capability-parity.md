# Native capability parity inventory

The [machine-readable inventory](../../../tests/fixtures/routing/parity.json) records 72 distinct CLI behaviors at the PAR-00 baseline: 46 in the bounded native routing milestone and 26 explicit exclusions. Aliases such as `ask`/`infer`, `lint`/`check`, and `fetch`/`download` share their behavior row. The inventory is the frozen denominator; passing tests and the evidence below determine current coverage without rewriting its baseline entries.

Each row identifies its command, inputs and options, output or artifact, effect, host or network requirement, baseline registry relationship, phase owner, and equivalence obligation or exclusion. The legacy `acorn.check_research_activity_data` entry performs schema validation. The routed `acorn.check` binding calls the full `analyze_paths` service and reports category status and structured findings for local, remote, Git, and OCI selections. `acorn.check::fixes` uses the configured inference backend to return validated proposals and nonexecuting unified previews. The `acorn.diff` binding shares semantic diff and similarity operations with the direct CLI. Gather has separate local, remote, and report-write routes. Format has preview, enrichment, and authorized apply routes; crosswalk preview/apply returns field-loss warnings. The older format and export tools cover narrower RAD operations.

The bounded milestone uses the existing command behaviors recorded in the routing plan. In particular, check includes category status, offline handling, and typed findings; effectful families require explicit destination and apply authority. Direct prompt and MCP commands remain available while generic adapters develop their routed bindings. Clipboard and TUI interaction, persistent servers, infrastructure or credential creation, automatic repair, unrestricted automation, and durable intake operations are counted as exclusions.

## Extraction seams

`acorn-lib::analyzer::host::service::analyze_paths` and its structured `AnalysisReport` provide the reusable analysis operation. The routed bindings delegate to it and to `AnalysisReport::suggest_fixes`; the CLI still owns presentation. `acorn.diff` uses shared `semantic_compare` and `similarity_compare` operations in `io/mcp/tools/native/diff.rs`; the direct CLI delegates to those operations. Gather uses the same `Records::from` discovery and `Report::serialize` JSON output as the direct command. Plain format and ACRE syntax preservation now have shared library operations called by both CLI and native routes; provider enrichment uses the existing `Pipeline`, and crosswalk conversion uses `StandardCrosswalk`. The feature-gated `io::export::pdf` operation now owns Chromium executable selection, session cleanup, and HTML-to-PDF rendering; direct PDF export calls it. A configured-Chrome fixture test rendered valid direct and shared PDFs, checked invalid executable failure, and preserved source bytes. `io::export::powerpoint` now owns reference-deck transformation and artifact creation with caller-provided fallback image bytes; the direct command delegates to it and report slides reuse its OOXML helpers. Direct and shared single-input slide parts match, and a two-input shared deck contains both slides. Other capability leaves must use an existing library service where one is present; if a command combines operation and presentation, its named native phase extracts only that operation before registration. The PAR-00 inventory identifies each leaf and owner so this can be checked before work on that leaf begins.

PAR-28 closes `download.model` and `download.preview` with `acorn.download::model` and `acorn.download::model::preview`. Both use the direct model selection planner; explicit acquisition uses the direct transfer operation. Focused tests compare local copy and mocked HTTP acquisition with the direct command, reject offline remote selection, and prove that preview writes no artifact. Native tests require exact output authority and reject cancellation, existing output without overwrite, and paths outside the permitted root.

PAR-13 closes `report.local` and `report.publish` with `acorn.report::local` and `acorn.report::publish`. The direct command and native route share project update selection, output naming, and manifest writing; the native route follows the same title, legend, project PDF, immutable package, and callback operations. Focused tests compare direct and native local manifests and valid project PDFs, enforce exact local and publication authority, reject offline publication, and keep receipts free of credentials. Mocked GitLab package tests prove ordered publication, checksum validation, no-change ledgers, and identical-content retries. PDF metadata changes its checksum between renders, so the parity test verifies each manifest checksum against its own PDF and compares the remaining manifest fields.
